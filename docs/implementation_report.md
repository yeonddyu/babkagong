## 11. 같은 식당만 반복 추천되던 문제 (2026-11-20, 사용자 지적)

원인 (데이터·프롬프트가 아니라 후보 선택 로직)
- 반경 700m 안 후보는 충분함: 강남역 1,705곳(메뉴 정보 374곳), 역삼역 1,456곳(322곳) — 서울관광재단 식당기본정보.
- 그런데 후보 Tool 이 항상 **가장 가까운 30곳**을 돌려주고, Agent 는 그중 **가장 가까운 10곳**만 상세 조회 → 같은 지역은 늘 같은 식당.
- 가까운 10곳 다수가 메뉴 정보가 없어 예산 조건이면 2곳만 남는 경우도 있었음 (역삼역 1만 2천원 이하).

수정
- `search_restaurant_candidates` 에 `order=varied`·`seed` 추가 (기본값은 기존과 같은 `distance`): 거리 구간별로 섞어 고르고 메뉴 정보 있는 곳 우선, `menu_available`·`pool_size` 출력.
- Agent 는 요청마다 새 seed 로 `varied` 사용 (seed 는 tool_call 이벤트 로그에 남아 재현 가능). 단 '많이 걷기 싫어' 요청은 가까운 순 유지.
- 조건 판정·점수(거리 감점 포함)·제외 규칙은 그대로.

### 11-1. 거리 제한 요청에서 추천이 1~2곳으로 줄던 문제 (같은 날, 위 수정의 부작용)
- 원인: `varied` 가 700m 전체에서 후보를 고른 뒤 '도보 3분'·'200m 이내' 판정에서 대부분 제외됨. 또 충족 1곳 이상이면 남은 후보를 확인하지 않음.
- 수정: 거리·도보 제한을 판정과 같은 추정식으로 반경(`radius_m`)으로 바꿔 그 안에서만 고름. 충족이 1~4곳이면 남은 후보 묶음을 이어서 확인(재계획 아님, 0곳이면 기존 재계획 흐름).
- 실제 데이터 (회당 추천 수, 수정 전 → 후): 강남역 도보 3분 1 → 5, 역삼역 200m 2 → 5, 강남역 도보 5분+1만원 1 → 5. 거리 제한을 모두 지킴, 응답 약 1.3초.
- 출구 기준('11번 출구 근처')은 아직 지원하지 않음 — 역 중심 기준으로 계산되고 출구 표현은 무시됨.

## 12. 출구 기준 검색 ('N번 출구 근처') (2026-11-20, 사용자 요청)

- 출구 좌표: 카카오 로컬 키워드 검색 '{역} {N}번출구' → 분류가 '지하철출구'로 끝나고 이름이 '{역} … {N}번출구' 인 장소가 정확히 1곳일 때만 채택.
  실제 API 확인: 강남역 1~12번(3~6번은 신분당선 출구), 역삼역 1~8번. 캐시 `station_exits` 에 저장 (최초 1회 약 28회 호출).
- 'N번 출구' 는 규칙으로만 추출 (LLM 값 사용 안 함), 출구가 둘 이상 언급되면 정하지 않음. 지역만 바꾼 후속 요청이면 이전 출구는 버림.
- 후보 Tool 이 출구 좌표를 기준점으로 거리 계산 → 판정·점수·도보 추정·요약·카드·지도가 모두 같은 기준. 응답에 `origin`, 추천마다 `distance_from`.
- 없는 출구(예: 역삼역 9번)는 역 중심으로 찾고 '확인된 출구: 1~8번' 안내를 notices 에 표시.
- 지도: 기준 출구 핀(초록)과 범례 '거리 기준: …'.

## 13. 서울 지하철역 전체로 확장 (2026-11-20, 사용자 요청)

범위: 요구사항정의서의 기본 범위(강남역·역삼역)를 사용자 요청으로 넓힘. '지역 = 역' 방식 유지 (자유 지역명은 '홍대'→세종캠퍼스, '을지로'→긴 도로처럼 기준점이 애매해 채택하지 않음).

데이터
- 서울관광재단 식당기본정보·운영정보·메뉴: 두 역 주변만 남기던 필터를 없애고 서울 전역을 SQLite 로 저장
  (식당 166,453곳 121MB, 운영정보 56MB, 메뉴 573,965행 76MB, 좌표 색인). 다시 받을 때는 임시 파일에 쓴 뒤 교체.
- 강남구 인허가(보완): 두 역 주변 → 강남구 전체. 강남구 밖은 보완 출처 없음 (응답 notes 에 안내).
- 역 목록: 서울시 역사마스터 정보(784행) → 이름(괄호·'역' 제외)과 500m 안 노선을 한 역으로 묶고,
  반경 500m 안에 서울관광재단 식당이 없는 역(서울 밖)은 제외 → 311곳. 같은 이름이 떨어져 있으면 노선 표시(신촌역(2호선)/(경의중앙선)).
  강남역·역삼역은 기존 좌표 유지. 목록은 서버 시작 시 백그라운드·캐시 구축 스크립트·모르는 역 요청 때 받고,
  요청 처리 중에는 저장된 목록만 읽는다 (인사 등 Tool 이 필요 없는 요청은 외부 호출 없음 유지).

- 지역은 코드로 확인한 역 이름만 (발화: 'OO역' → 별칭(홍대·건대·서울대·고터) → 'OO에서/근처' 순, 긴 이름 우선,
  '방학'·'서울'처럼 흔한 낱말은 이름만으로는 역으로 보지 않음). LLM 값은 역 목록에 있고 발화에 그 이름이 있을 때만 사용.
- 인접 지역 재계획: 2km 안 가장 가까운 역. 출구 좌표는 (역, 번호)별로 요청 시 조회해 누적.
- `GET /api/stations`, 대화 `area` 는 역 목록에 없으면 무시. 화면: 강남역·역삼역 버튼 + 역 검색(목록에 없는 이름은 거부).
